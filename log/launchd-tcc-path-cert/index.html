맥 자동화에서 네 번 멈춘 날

2026년 8월 28일Importants Studio

2026년 8월 28일, 맥에서 블로그 발행 자동화를 붙이기 시작했습니다. launchd가 매일 10시 30분에 셸 스크립트를 실행하고, 스크립트가 claude CLI를 헤드리스로 띄워 글을 쓴 뒤 GitHub PR을 여는 구조였습니다. main에는 직접 push하지 않기로 했습니다. PR을 머지하는 것이 발행이 됩니다.

처음에는 스크립트를 바탕화면 폴더에 뒀습니다. 작업할 때 가장 눈에 잘 들어오는 위치였고, 터미널에서도 문제없이 실행됐습니다. 그런데 launchd는 그 파일을 읽지 못했습니다. macOS의 TCC가 바탕화면을 보호 영역으로 잡기 때문이었습니다.

첫 번째 위치에서 멈췄습니다

스크립트를 ~/blog-automation으로 옮겼습니다. 바탕화면에는 원래 위치처럼 보이도록 심볼릭 링크만 뒀습니다. 파일을 옮긴 뒤에는 launchd가 스크립트를 읽었습니다.

다음에는 터미널에서 되던 claude 명령이 자동 실행에서 없다는 메시지가 나왔습니다. 처음에는 CLI 설치가 잘못됐다고 생각했습니다. 터미널에서는 계속 실행됐기 때문에 틀린 판단이었습니다. launchd는 로그인 셸의 PATH를 물려받지 않습니다.

스크립트 안에서 PATH를 직접 지정했습니다. claude라는 터미널 래퍼를 부르는 대신 실제 바이너리 경로인 ~/.local/bin/claude를 쓰게 바꿨습니다. 이 문제도 로컬에서는 보이지 않았습니다.

GitHub에서 다시 멈췄습니다

글을 쓰고 PR을 여는 단계까지 갈 것 같았지만, git push가 거부됐습니다. 이 맥에는 회사 계정의 HTTPS 자격증명과 SSH 키가 저장돼 있었습니다. 개인 블로그 저장소에 push할 때도 그 계정을 쓰고 있었습니다.

개인 계정으로 로그인한 gh CLI를 credential helper로 붙여 해결했습니다. 자동화가 실행하는 git도 개인 계정 자격증명을 쓰게 됐습니다.

PR을 열고 나면 GitHub Pages가 커스텀 도메인에서 HTTPS로 열려야 했습니다. 그런데 인증서가 나오지 않았습니다. 15시간을 기다렸지만 그대로였습니다. 기다리면 발급될 것이라고 본 것도 틀렸습니다.

커스텀 도메인을 뺐다가 다시 넣었습니다. 그러자 1분 만에 HTTPS 인증서가 발급됐습니다.

파일 위치, PATH, GitHub 자격증명, HTTPS 인증서까지 네 개 모두 로컬에서는 되는데 자동 실행에서는 안 되는 부류였습니다. 이 네 개를 다 밟고 나서야 첫 자동 PR이 열렸습니다. 세 번째 블로그를 열 때는 같은 자리에서 걸리지 않아 30분 만에 끝났습니다.
