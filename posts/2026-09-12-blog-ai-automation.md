AI로 블로그를 자동 발행해 보려는 분이라면, 글을 만드는 단계보다 그다음이 더 궁금하실 수 있습니다. 매일 여러 편을 올릴 수 있는지, 사람이 어디까지 봐야 하는지, 방문과 수익으로 이어지는지가 실제 판단 기준이 됩니다.

이 구조는 한 번 설정한다고 끝나지 않았습니다. 4주 동안 여섯 개 블로그를 운영하며 자동화가 멈추는 지점과, 글은 올라가도 성과가 따라오지 않는 지점을 직접 확인했습니다. 운영 중에는 처음 설계할 때 보이지 않던 함정도 있었습니다.

## 먼저 결론부터

- 여섯 개 블로그에서 하루 12편을 발행하는 구조를 4주째 돌렸고, 공개 글은 232편입니다.
- 글 12편은 26~36분 안에 GitHub PR로 올라왔으며, 순차 실행 때 걸리던 2시간을 블로그별 병렬 실행으로 줄였습니다.

```text
실행 시각: 매일 10:30
배포 경로: GitHub PR → 사람 검수·머지 → GitHub Pages
main 직접 push: 차단
```

- 호스팅·이미지·서버 비용은 0원이었고, 도메인값과 구독료만 들었습니다.
- 지난 28일 성과는 971 페이지뷰, 세션 595, 사용자 514명이며 하루 평균 페이지뷰는 35입니다.
- 검색 노출은 942회, 클릭은 18회였고 애드센스 환산 수익은 월 1,500원에서 5,000원 사이입니다.
- 자동화는 검색 수요 판정, 표의 사실 검수, 실행 실패 복구, AI 문체 관리 없이는 운영되지 않았고 애드센스는 두 번 거절됐습니다.

## 매일 열두 편은 PR로 모입니다

구조는 단순합니다. macOS launchd가 정해진 시각에 셸 스크립트를 띄우면 스크립트가 블로그별 에이전트를 병렬로 실행하고, 각 에이전트는 주제를 고른 뒤 출처를 대조해 글을 쓰고 GitHub PR을 열며, 사람은 그 PR을 검수하고 머지한 뒤 GitHub Pages가 배포합니다. 배포는 사람이 정합니다.

main 브랜치 직접 push는 막아뒀습니다. 원고 생성과 공개를 분리한 덕분에, 자동으로 나온 글이 곧바로 사이트에 반영되지는 않습니다. 이 구분은 틀린 정보나 어색한 문장이 발견됐을 때 마지막으로 멈출 수 있는 지점입니다.

## 병렬 처리와 비용

처음에는 작업을 순서대로 돌렸습니다. 12편에 2시간이 걸렸습니다. 블로그별 병렬 실행으로 바꾼 뒤에는 같은 분량이 26~36분 안에 PR로 올라왔습니다.

비용 구조도 확인했습니다. 호스팅, 이미지, 서버 비용은 모두 0원이었습니다. 도메인값과 구독료 외에 자동 발행을 위해 추가로 든 비용은 없었습니다. 다만 시간 단축이 방문이나 클릭 증가를 보장하지는 않았습니다.

## 검색 수요의 판정

여기서 갈립니다. 에이전트가 자동으로 고른 주제는 글로 만들기에는 충분해 보여도 실제 사람이 찾는 검색어인지 확인되지 않으며, 은퇴 블로그에는 경로우대 할인율 글이 올라온 적이 있었고, 이 글은 블로그 주제와 검색 수요가 맞는지 별도로 판단해야 한다는 사례가 됐습니다. 그래서 단계를 넣었습니다.

현재는 네이버 자동완성으로 실검색어인지 판정하는 단계를 거칩니다. 이 단계는 원고 품질을 높이는 장치라기보다, 처음부터 수요가 없는 주제로 시간을 쓰지 않기 위한 필터입니다.

지난 28일 실측은 페이지뷰 971, 세션 595, 사용자 514명이었습니다. 하루 평균 페이지뷰는 35입니다. 검색 노출 942회 중 클릭은 18회였습니다. 글이 생성되는 속도와 읽히는 속도는 다른 문제였습니다.

## 검수와 복구의 빈틈

멈춤은 조용했습니다. 맥이 꺼져 있던 날에는 launchd가 실행하지 못한 일정을 다시 처리하지 않았고 하루치 12편이 통째로 사라졌으며, 에이전트는 글을 모두 작성한 뒤 커밋 직전에 한도에 걸려 파일만 남겼고, 다음 날 배치는 작업 폴더가 깨끗하지 않다는 이유로 시작조차 못 했습니다. 복구 절차가 필요합니다.

사실 검수도 PR 단계에서 잡혔습니다. 제주항공 취소 위약금 표의 마지막 줄이 공식 규정과 달랐습니다. 숫자가 맞아 보이는 표는 구조까지 맞는다고 넘기기 쉬워서, 표는 줄마다 원문과 대조해야 했습니다.

## 수익과 AI 문체의 기록

AI 티를 줄이기 위해 금지 목록을 문서로 만들고, 에이전트가 매번 읽게 했습니다. 4주 뒤 201편에서 상투구를 세었을 때 7편이었고 비율은 3퍼센트였습니다. 문체 규칙은 적용 여부를 셀 수 있어야 관리할 수 있었습니다.

수익은 아직 작았습니다. 애드센스 환산치는 월 1,500원에서 5,000원 사이였습니다. 애드센스는 두 번 거절됐고, 사유는 「가치가 별로 없는 콘텐츠」였습니다. 발행량이 있어도 콘텐츠 가치 판단을 통과한다는 뜻은 아니었습니다.

## 마무리

다음 작업은 발행량을 더 늘리는 일이 아닙니다. 검색어 판정 단계를 유지하고, 표와 규정 원문을 검수하며, 실패 뒤에 남은 파일을 정리하는 흐름을 먼저 고정해야 합니다. PR에 모인 원고를 사람이 검토하는 시간도 운영 비용으로 잡아야 합니다.

여기 적은 수치는 공식 문서에서 찾을 수 있는 내용이 아닙니다. 여섯 개 블로그를 4주간 실제로 돌렸을 때 남은 방문 기록, 실행 실패 기록, 검수 기록이기 때문입니다. 도구의 기능 설명만으로는 자동 발행 뒤에 남는 운영 문제와 읽히는 글의 조건을 대신 확인할 수 없습니다.
