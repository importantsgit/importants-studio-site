커버 한 장도 작업량이 쌓입니다.

우리처럼 블로그 여섯 개에 하루 12편을 올리는 일정에서는 글마다 필요한 커버 이미지를 한 장씩 채워야 하므로, 한 달에 360장을 만들면서 제작 시간과 비용을 같은 기준으로 관리해야 하고, 한 장의 예외가 쌓여 게시 일정 전체를 늦추지 않게 해야 합니다.

손이 멈추면 안 됩니다.

제미나이 이미지 생성을 검색해 무료라는 말을 보고 들어온 분이라면, 앱에서 한 장을 만드는 일과 매일 여러 장을 운영하는 일 사이에 생각보다 큰 차이가 있다는 점부터 살펴야 합니다. 비용을 확인한 뒤에도 작업 흐름에서 걸리는 지점이 남았습니다.

## 먼저 결론부터

- 제미나이 이미지 API의 무료 한도는 0이었으며 API 사용은 유료만 가능했습니다.
- 검색에 남아 있는 하루 500장 무료라는 정보는 직접 확인한 API 조건과 달랐습니다.
- 구독 중인 제미나이 앱에서 사람이 직접 이미지를 만들면 추가 비용은 0원이었습니다.
- 앱 출력 이미지의 오른쪽 아래 워터마크는 고정 위치에 있어 자동 보정 대상으로 잡을 수 있었습니다.

```yaml
watermark_area:
  x: 89.5% ~ 93.0%
  y: 81.2% ~ 87.4%
  reference: 각 가로줄의 왼쪽
  replace: 낮은 채도 픽셀만
```

- OpenAI 이미지는 워터마크가 없었지만 1536 x 1024 출력 비율은 3대 2 하나였습니다.
- 커버 18장은 격자 시트로 전수 확인했고, 그중 3장은 다시 처리했습니다.

## API 비용은 따로 확인해야 합니다

검색 결과만으로 예산을 잡기 어렵습니다.

제미나이 이미지 API를 쓰려고 직접 확인했을 때 무료 한도는 0이었는데도 하루 500장을 무료로 쓸 수 있다는 글이 검색에 남아 있었고, 실제 운영 계획은 그 숫자를 기준으로 세울 수 없었습니다.

API는 유료만 가능했습니다.

이 차이는 월 360장을 만드는 일정에서 특히 큽니다. 무료 API를 전제로 자동 생성 파이프라인을 먼저 만들면, 비용 조건을 다시 맞추는 동안 작업 방식도 함께 바꿔야 하기 때문입니다.

## 사람 검수가 들어가는 작업 흐름

그래서 앱 안에서 제작했습니다.

구독 중인 제미나이 앱에서 사람이 직접 이미지를 만들고 올리는 방식은 추가 비용이 0원이었습니다. 글을 쓰는 에이전트는 PR 본문에 영문 프롬프트를 통째로 남기고, 담당자는 그 문장을 복사해 앱에 붙여 넣은 뒤 나온 그림을 업로드합니다.

완전 자동화는 아니었습니다.

대신 프롬프트를 다시 작성하는 시간을 없앴습니다. 사람이 확인해야 하는 단계가 남아 있어도, 커버 이미지의 문맥과 결과물을 함께 보는 흐름이 됩니다.

## 워터마크 위치는 고정이었습니다

앱에서 나온 그림에는 오른쪽 아래 워터마크가 들어갔습니다.

2752 x 1536 크기에서 워터마크는 가로 89.5~93.0퍼센트, 세로 81.2~87.4퍼센트 자리에 항상 같은 위치로 나타났으므로, 이미지마다 찾는 과정 없이 해당 범위를 자동 보정 영역으로 정할 수 있었습니다.

위치 정보가 기준이 됐습니다.

처음에는 그 영역을 주변 색으로 덮었습니다. 배경색이 하나인 이미지에서는 문제가 없었지만, 위아래 배경이 갈리는 그림에서는 덮은 부분이 띠처럼 떠 보였습니다. 그림 전체에서 참조 색을 하나만 뽑은 방식이 원인이었습니다.

## 색을 줄마다 다시 읽는 방식

참조 색의 범위를 좁혔습니다.

가로줄마다 그 줄의 왼쪽에서 참조 색을 다시 뽑고, 낮은 채도 픽셀만 바꾸도록 고치자 배경 변화에 맞는 색을 유지할 수 있었으며, 워터마크 옆을 지나가는 유채색 곡선은 그대로 남길 수 있었습니다.

첫 결과에는 문제가 남았습니다.

참조 색을 뽑는 자리가 그래픽 위에 걸리면서 가로 색 줄이 생겼습니다. 참조 위치를 옮긴 뒤 낮은 채도 픽셀의 중앙값을 쓰도록 바꾸니 이 줄이 사라졌습니다. 이 과정은 이미지 한 장만 보고 끝내기보다 여러 결과를 모아 확인해야 드러납니다.

## 비용과 비율을 함께 봅니다

비교용으로 OpenAI 이미지 값도 직접 재봤습니다.

| 출력 조건 | 사용량과 비용 | 워터마크 | 비율 |
|---|---:|---|---|
| 1536 x 1024 중간 품질 | 1568토큰, 약 18원 | 없음 | 3대 2 |
| 1536 x 1024 고품질 | 1372토큰, 60~80원 | 없음 | 3대 2 |

워터마크가 없는 선택지는 분명했습니다. 다만 커버 디자인에서 다른 비율이 필요할 때는 3대 2 하나만 제공되는 조건도 같이 봐야 합니다.

18장의 커버는 격자 시트로 만들어 눈으로 전수 확인했습니다. 자동 보정 결과 중 3장은 다시 처리했고, 이 확인 단계가 있어야 색 띠나 그래픽 훼손을 놓치지 않습니다.

## 마무리

다음 작업에서는 PR 본문에 영문 프롬프트가 빠지지 않게 하고, 생성 뒤에는 보정 결과를 격자 시트로 모아 확인하는 순서를 고정하면 됩니다. 월 360장처럼 수량이 많은 일정에서는 한 장씩 열어 보는 방식보다 재처리 대상을 빠르게 골라낼 수 있습니다.

여기서 직접 확인한 무료 한도, 앱 출력의 워터마크 좌표, 색 보정 실패 사례는 서비스 기능 설명만으로 알기 어려운 운영 기록입니다. 공식 문서는 특정 이미지의 배경과 그래픽, 실제 출력 위치까지 보장하는 작업 절차를 담지 않으므로, 이런 조건은 자신의 제작 흐름에서 한 번 검증해 두는 편이 안전합니다.
