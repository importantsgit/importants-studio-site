## 멈춘 오후

9월 20일 배치는 10시 30분에 시작했습니다. 오후 1시 30분까지 아무것도 나오지 않았습니다.

에이전트 프로세스 5개는 살아 있었지만, 3시간 동안 CPU를 3초 쓴 채 세션 파일 하나도 생기지 않고 API 호출 기록도 없는 상태로 첫 요청을 보내기 전에 멈춰, 오후 1시 30분까지 떠 있었습니다.

화면도 찍어 확인했습니다. 권한을 묻는 창이나 진행을 막는 대화상자는 없었습니다. 열린 파일을 봤을 때도 네트워크나 잠금에 걸린 흔적은 없었습니다.

10시 30분부터 오후 1시 30분까지 사라지지 않은 프로세스는 CPU를 완전히 0초만 쓴 것도 아니었지만, 세션 파일과 API 호출 기록이 모두 비어 있어서 실제 작업이 어디까지 갔는지는 첫 요청 전이라는 것만 확인할 수 있었습니다.

## 같은 명령은 바로 끝났습니다

자동 실행에 넣은 명령을 내 터미널에서 그대로 실행했습니다. 같은 저장소를 쓰고 같은 플래그와 같은 세션 옵션을 넣은 뒤 표준입력까지 맞춘 명령은 바로 응답했고 즉시 끝났습니다.

이 차이가 가장 이상했습니다. 자동 실행 쪽에서는 5개 프로세스가 3시간 동안 CPU를 3초 쓰며 첫 요청도 보내지 못했습니다. 명령과 저장소, 플래그, 세션 옵션, 표준입력이 같았던 터미널에서는 멈추는 구간이 없었습니다.

전날 오후에는 CLI 새 버전이 설치돼 있었습니다. 9월 20일 배치는 그 버전의 첫 자동 실행이었습니다. 정황은 그쪽을 가리켰습니다. 증거는 없습니다.

멈춘 프로세스를 모두 죽였습니다. 내 셸에서 같은 스크립트를 다시 띄웠습니다. 12초 만에 세션 14개가 열렸고, 26분 뒤 12편이 PR로 올라왔습니다. 스크립트와 프롬프트에는 문제가 없었습니다. 실행 주체에 따라 결과가 갈렸습니다.

## 다음 날에는 재현되지 않았습니다

다음 날 같은 시각 자동 실행은 정상이었습니다. 26분 만에 12편이 나왔습니다. 전날과 같은 멈춤은 다시 나오지 않았습니다.

CLI 새 버전이 원인인지도 확인하지 못했습니다. 자동 실행 환경에서만 생긴 일인지, 그날 한 번의 상태 문제였는지도 남아 있습니다.

원인을 못 찾았습니다. 재현이 안 되니 고칠 수도 없습니다. 지금은 안 돌았을 때 알아차리는 쪽을 먼저 만들 생각입니다(다음 실행에서 다시 멈출지는 알 수 없습니다).
